# 系统架构

## 总体结构

```text
浏览器
  │  HTTP / JSON
  ▼
Vue 3 + Vite 前端
  │  /api
  ▼
Flask 后端
  ├── OpenAPI 参数/响应校验
  ├── 行情与算法适配
  ├── 异步回测 worker
  └── SQLite 回测任务库
          │
          ▼
Python 算法模块
  ├── AkShare / Tencent 数据适配
  ├── SQLite 行情缓存
  ├── 相关性与传统策略
  ├── 回测与策略排行
  └── 次日模拟配置
```

仓库采用 monorepo。前端、后端和算法模块可以独立测试，但跨模块字段必须以 [OpenAPI 契约](../packages/contracts/openapi.yaml) 为准。

## 模块职责

### 前端：`apps/frontend`

负责页面交互、图表展示、任务轮询和错误提示。前端只调用后端 API，不直接访问 AkShare、SQLite 或 Python 算法代码。后端不可用时只提供有限的固定展示兜底，不伪造随机业务结果。

### 后端：`services/backend`

负责 HTTP 路由、输入输出校验、统一错误响应、CORS、算法调用和异步回测任务。回测元数据及结果存入 `services/backend/var/backtests.db`，后台 worker 原子领取排队任务。

### 算法：`services/algorithms`

负责数据下载和缓存、交易日处理、相关性、均线交叉、动量反转、回测、排行与配置。行情默认保存到 `data/processed/market_data.db`，并在数据源异常时优先使用最后一次成功缓存。

### 契约：`packages/contracts`

保存 OpenAPI 和共享 Schema。接口路径、字段、枚举、错误结构或状态语义变更时，必须先更新契约，并在同一 PR 中同步调用方、实现和测试。

## 关键数据流

1. 数据更新命令从第三方数据源拉取行情，校验后写入 SQLite 缓存。
2. 前端请求市场、资产或策略数据，后端读取缓存并返回状态信息。
3. 前端提交回测，后端持久化任务并立即返回 `jobId`。
4. worker 执行策略和回测，将结果写回任务库；前端轮询直到完成或失败。
5. 相关性、排行和配置请求由后端调用算法模块同步计算并返回。

## 失败与降级

- 第三方数据源失败：保留旧缓存，并通过 `/api/data/status` 标记 `stale` 或 `failed`。
- 单项首页请求失败：前端保留其他成功模块，并显示对应错误。
- 回测执行失败：任务进入 `failed`，错误以统一结构返回。
- 服务重启：排队任务保留在 SQLite；运行中断任务需要运维流程确认后重新入队。

## 部署边界

GitHub Pages 只承载静态前端。完整系统还需要可运行 Python 的后端环境、持久卷、HTTPS、反向代理、收盘后更新调度、监控告警和备份恢复。课程阶段不连接券商，不执行真实交易。
