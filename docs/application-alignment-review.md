# 项目现状与应用材料对齐审查

审查日期：2026-08-30

## 结论

当前代码已经完成传统量化功能的最小业务闭环，先前文档中“后端接口未实现、主要依赖前端 mock”的描述已经失效。项目仍不能描述为完整生产系统：GitHub Pages 只部署静态前端，云端 Flask API、数据更新调度、监控、备份、强化学习策略和实盘交易能力尚未完成。

## 已完成并可验证

- Vue 前端五个业务模块和统一 API 客户端。
- OpenAPI 契约、统一错误结构和全部 Flask 路由。
- A 股/ETF 资产池、AkShare/Tencent 数据适配和 SQLite 行情缓存。
- 数据状态、增量更新、旧 CSV 导入与缓存降级。
- Pearson 相关性、均线交叉和动量反转。
- 无未来函数回测、异步任务持久化、策略排行与次日模拟配置。
- 前端、后端和算法自动化测试及 CI。
- GitHub Pages 静态前端构建与发布。

## 仍需完成

1. 部署公网 Flask API，并配置持久化目录、HTTPS、CORS 和进程托管。
2. 配置交易日收盘后的数据更新调度，增加数据新鲜度告警。
3. 完成日志、监控、数据库备份和故障恢复演练。
4. 在真实公网环境完成一次全流程联调与答辩演练。
5. 按统一评估口径逐项实现 DQN、PPO 和多智能体策略。
6. 如未来涉及实盘，再单独建设账户、权限、审计、独立风控与人工确认。

## 对材料表述的修正

| 容易误解的说法 | 准确说法 |
| --- | --- |
| “系统已部署上线” | “静态前端已支持 Pages 发布，完整 API 部署仍待完成” |
| “支持多种 AI 策略” | “当前实现两种传统策略，强化学习策略处于规划阶段” |
| “支持实时交易” | “当前只提供历史分析和次日模拟配置，不连接券商” |
| “数据异常时自动生成结果” | “数据异常时使用最后成功缓存并显式报告状态，不随机伪造结果” |
| “回测任务在内存中执行” | “任务由 SQLite 持久化并由后台 worker 异步执行” |

## 答辩可强调的工程设计

- 契约优先：OpenAPI 是跨模块接口唯一依据。
- 数据可追踪：记录缓存状态、更新时间和失败原因。
- 结果可复现：统一资产池、回测区间、成本和指标口径。
- 降级不造假：服务失败时显示不可用或旧缓存，不生成随机业务数据。
- 任务可恢复：回测元数据和结果落入 SQLite，而不是只存在于进程内存。
- 风险边界明确：教学研究用途，不承诺收益，不连接真实账户。
