# 申请书与仓库对照检查

检查基准：《大创-量化 项目申请书》与当前仓库。检查日期：2026-07-25。

## 已对齐

- 前端保留申请书要求的五个模块：市场概况、资产相关性、策略回测、策略排行、
  下一交易日模拟配置；
- 资产口径已从美股 ticker 改为六位 A 股/场内 ETF 代码；
- 页面已改为“交易日收盘后日更”，不再宣称盘中实时；
- 已删除随机生成的回测、排行和配置成绩；
- OpenAPI、Flask 占位路由、Python 数据模型和前端 API 客户端已经统一；
- 相关性限制 2–10 个资产；
- 回测契约包含总收益、年化收益、最大回撤、Sharpe、Alpha、Beta；
- 配置结果强制标识研究用途，不提供真实下单能力。

## 仍未完成

以下内容只有接口或占位，不能在答辩中描述为“系统已经实现”：

1. AkShare 资产池、历史行情、市场概况和收盘后增量更新；
2. Pandas 数据清洗、复权、缺失值与异常值处理；
3. 均线交叉和动量反转策略；
4. 相关矩阵真实计算；
5. 含成本且无未来函数的回测引擎；
6. 异步回测任务持久化；
7. 真实策略排行和下一交易日配置；
8. DQN、PPO、多智能体策略；
9. CSV 到 SQLite 的迁移、云服务器定时任务、监控和备份。

## 需要关注的风险

- 申请书中“已经实现完整回测逻辑”“AkShare 可稳定获取”等完成态表述，与仓库目前的
  `NotImplementedError`/`501 NOT_IMPLEMENTED` 不一致。若申请书尚可修改，应改成
  “已定义接口、正在实现”；若已提交，应优先补齐这两项并保留测试证据。
- 申请书第一阶段计划为 2026 年 4–5 月；当前已是 2026 年 7 月，仓库尚未完成
  第一阶段后端与算法，需要更新内部排期并尽快形成可运行最小闭环。
- 前端在后端未实现时会展示明确的“待接入”状态。演示时不能把目录占位当成真实
  行情或策略结果。
- AkShare 是外部数据源，接口可能变化或暂时失败。必须缓存最后一次成功数据，
  记录更新时间，并让 `/data/status` 能暴露 stale/failed。
- SQLite 符合申请书早期规模；若以后多人并发或任务量明显增加，再评估 PostgreSQL，
  不要在当前阶段同时引入两套数据库。

## 最小可答辩闭环

优先完成以下一条链路，再扩展 AI：

`收盘后拉取 30–50 个资产 → 清洗并保存 → 市场概况/相关性 → 两个传统策略 →
异步回测 → 日更排行 → 下一交易日模拟配置 → 前端展示`

闭环验收需要保存：一次 CI 成功记录、一组固定测试数据、一个无未来函数的回测用例、
一次服务器定时更新日志和一份失败后保留旧数据的演示。
