# 数据修复与研究链路验证（2026-09-08）

## 结论

存在可复现的核心研究链路：腾讯真实日线 → 项目适配 → 隔离SQLite → Flask历史、相关性、回测、排行、模拟配置。不是完整沪深300或线上MVP验收。东方财富并非所有接口永久不可用，但前轮稳定性不足，不能把当前故障只归因于香港服务器；本轮不再重复请求东方财富。

建议继续采用“中证官方名单 + 修正后的腾讯股票历史 + 独立指数提供器”的方向；其中名单已有探测证据、股票研究链路本轮通过，独立指数接入及完整资产池仍待开发。首页全市场概览不应成为核心研究模块的强依赖，也不能将两只样本伪装成沪深300概览。

### 旧缓存保护与部署门槛

- 增加每代码/复权模式的成交量规范标记`tx-1.18.94-sz000-shares-v1`；受影响非空缓存没有匹配标记即拒绝命中，不能继续把未经核实的旧量用于研究。
- 行情和标记同事务读取/写入；部分日期重写不能给整段旧缓存背书；非版本化写入会清除标记；覆盖写失败不改变修订号或旧数据。
- 云端只读审计：000001、000333、000568、000725、000858五只，均qfq，各267行，2025-08-04至2026-09-07；无成交量规范标记，共1335行需重新核验/重拉，不代表逐行已证实错误。
- **不能直接只部署新代码**：保护生效后这五只未标记缓存会明确不可用。发布前停止旧版更新写入，制作一致性SQLite备份，在新隔离库按修正版全区间重拉并核对日期/价格/量额后切换；其他资产保留。生产迁移工具、演练和切换未完成，不直接对全部量乘100。
- 回滚保留原代码与对应数据库备份，停写后成套恢复；旧备份的单位风险仍需披露，不可宣称恢复为已校验数据。
