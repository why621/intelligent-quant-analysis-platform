## 4. M0可直接执行的小补丁顺序

1. 添加截图请求的回归用例，分别覆盖空参数、当天截止、硬编码基准；测试应先重现已知缺陷，不通过修改脚本参数掩盖页面错误。
2. 参数Schema驱动默认值与表单：均线5/20；动量10/5/-5来自服务端metadata，不在多个页面重复硬编码；切策略重置对应参数；验证必填、类型、边界和相互关系。缺metadata时禁用而非提交空对象。
3. 统一数据就绪状态与日期：优先使用服务端已发布latestTradeDate作保守默认上限，禁止无状态时回退当天；显示数据截至日期，支持数据晚到初始化且不覆盖用户已编辑值。后续按M1每资产覆盖进一步收紧共同区间。
4. 后端也校验可用范围并明确返回请求日期/可用日期/问题资产（新错误字段须同步契约）；手工越界不能只依赖HTML的max属性。正常范围真实上游故障仍按上游错误处理，不把所有503改成日期错误。
5. 基准来自后端支持目录，提供明确名称/类型；独立指数未完成前可明确选择旧ETF或无基准，结果披露此选择。禁止自动用ETF冒充CSI300；正式CSI300基准在M2完成。
6. 浏览器自动化/人工证据覆盖真实表单提交、服务端任务执行、图表渲染；脚本应使用页面真实请求，不另造“正确参数”。补任务ID展示、超时后恢复查询、防重复提交和组件卸载后不再更新。

## 5. 数据与发布设计重点

- 数据源选型按名单/股票历史/指数/概览拆开；不因单一接口失败换整个服务器，也不不断重试同一失败域名。
- 统一股票、ETF、指数身份；复权股票与价格指数比较需标明收益口径，若要求总收益指数另选相应序列。
- 历史结果保存名单版本、数据修订、策略参数/版本、成本和基准；旧结果不因刷新页面静默重算成新版本。
- 维护中的备份、校验及原子切换沿用CR-006；新名单/新源不覆盖旧库，先验证迁移与恢复。合法停牌/上市缺口应被分类，不能简单取消完整性检查。
- Pages为HTTPS时后端必须有浏览器信任的HTTPS端点；临时HTTP IP仅回归，CORS不是认证或限流。公开服务前补请求体/并发/任务频率限制与滥用保护，是否需要登录依展示范围决定。
- 部署必须协调前端与后端版本。此前只升级后端保留旧前端，不能用reload Nginx当作前端业务代码已更新。
